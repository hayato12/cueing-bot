# ADR 0004：MVP の音声解析は Rekordbox の解析 ＋ Demucs で始め、自前の拍検出や構造解析モデルは入れない

- 状態：**承認**（2026-10-30、オーナー）
- 関係する記録：[ADR 0002](0002-python-and-tooling.md)、[ADR 0003](0003-read-library-from-db-copy.md)、[スパイク 1](../spikes/01-vocal-detection.md)、[スパイク 2](../spikes/02-phrase-analysis.md)、[requirements.md](../requirements.md)（N7・N8・N11）

## 背景

CLAUDE.md の未決定事項「音声解析ライブラリ」を決める。候補は librosa、madmom、essentia、all-in-one 系の構造解析モデルなどだった。

ここで決めるのは **MVP で何を依存に入れるか** だけにする。推定のルールの中身（ボーカルの音量とフレーズの区切りをどう組み合わせるか）はスプリントで決める（スパイク 1 の「決まったこと」）。推定部分は差し替えられる形にする（CLAUDE.md 8 章）ので、あとから道具を足すのは難しくない。

前提：

- **拍・小節は Rekordbox のグリッドを使う。** 自前の拍検出は MVP に入れない（development-process.md の MVP）。グリッドとフレーズは解析ファイルから読む（ADR 0003）
- **フレーズ解析は区切りの候補になる**が、どれを選ぶかが難しい（スパイク 1・2）
- **Demucs（htdemucs）での分離は M4 で 1 曲 15 秒前後・ピーク 3.6GB**（スパイク 1）。N7（平均 60 秒／曲）・N8（8GB 以下）に収まる。ボーカルの音量は「判断材料の 1 つ」として使えそう
- 処理はすべて Mac の中で行う（N11）

## 役割ごとの選択肢

| 役割 | 推奨 | ほかの案と選ばない理由 |
|---|---|---|
| 拍・小節・フレーズ | **Rekordbox の解析ファイル**（pyrekordbox、ADR 0003） | madmom・librosa・essentia の拍検出：MVP の対象外。オーナーはグリッドを直して使っているので、Rekordbox のグリッドが正解に近い |
| 音源分離（ボーカルを取り出す） | **Demucs `htdemucs`**（torch、MPS） | 分離しない（フレーズだけで推定）：スパイク 1 でボーカルの手がかりが効く曲があった。Spleeter：古く、新しい Python で入れにくい。ほかの新しい分離モデル：スパイクで確かめていない |
| 音源の読み込み（M4A・MP3 のデコード） | **ffmpeg**（Homebrew）を別プロセスで呼ぶ | Python のライブラリだけで読む：M4A を確実に読めるものが少ない。スパイク 1 は ffmpeg で問題なかった |
| 音量などの特徴量 | **numpy**（拍ごとの音量はスパイク 1 と同じく自前で計算） | librosa：便利な関数が多いが、MVP で要るのは拍ごとの音量くらい。必要になったらスプリントで足す |
| 構造解析モデル（all-in-one 系） | **MVP では入れない** | 拍・区切り・パートの種類をまとめて出してくれるが、依存（madmom・natten など）が新しい Python や M4 で入りにくいことがある。Demucs も中で使うので重い。Sprint 4 以降、ルールベースの数字を見てから比べる |

## 推奨

- MVP の解析の道具は **Rekordbox の解析ファイル（pyrekordbox）、Demucs、ffmpeg、numpy** の 4 つに絞る
- Demucs と torch は重いので、**依存のグループを分ける**（ADR 0002）。CI ではこれらを入れずにテストが回るようにする。分離した結果を使う部分は、テストでは保存済みの特徴量（拍ごとの音量の配列など）を入れて確かめる
- 分離した音声そのものは保存しない。保存するのは**拍ごとの音量などの特徴量だけ**にする（スパイク 1 と同じ。容量を抑え、N9 のやり直しで重い分離をし直さずに済む）
- Sprint 2 のルールベースは、まずフレーズとグリッドだけで M1（キューごとの的中率）を出す。Demucs のボーカルの音量を足して M1 が上がるかを比べるのは、**Sprint 3（MVP 完成）のあと** にする（2026-10-31 変更。Sprint 2 を軽くするため）。上がらなければ Demucs を外すことも考える

### 気になる点

- Demucs は更新が少ない。Python 3.12 で入るかは Sprint 0 で確かめる（ADR 0002。入らなければ 3.11 に下げる）
- 「ボーカルではなくメロディで入る曲」は、ボーカルの音量では見つからない。Demucs のほかの出力（other など）を使うかは、Demucs を足すときに考える

## 決定

- MVP の解析の道具は **Rekordbox の解析ファイル（pyrekordbox）、Demucs `htdemucs`、ffmpeg、numpy** にする
- 自前の拍検出（madmom・librosa・essentia）と構造解析モデル（all-in-one 系）は MVP に入れない
- Demucs と torch は依存のグループを分け、CI では入れない。分離した音声は保存せず、拍ごとの音量などの特徴量だけを保存する

## 結果

- CLAUDE.md の未決定事項「音声解析ライブラリ」を決定済みに移した
- 自前の拍検出や構造解析モデルを入れるときは、新しい ADR を書く
- ffmpeg は Homebrew で入れる前提を README に書く（Sprint 0）
